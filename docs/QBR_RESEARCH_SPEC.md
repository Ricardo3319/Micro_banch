# QBR：接收额度约束的跨主机批量重调度

确定日期：2026-09-26。当前用户授权优先于旧 FIRST_PAPER.md 的冻结约定。旧实验保留，新实验使用独立的 `batchsched` 入口。

**实验后状态：候选算法已实现，但正式实验不支持将 QBR 定为优于强基线的最终算法。** 选题决策见 [研究决策](RESEARCH_DECISION_2026-09-26.md)，完整结果见 [自动报告](../artifacts/qbr-main-v3/研究结果.md)。本文件保留候选方案及其可证伪标准。

## 要研究的问题

当入口反馈滞后、个别主机短时降低处理能力时，已分发请求可能积压在源主机。QBR（Queue Batch Rebalancing）通过本地主机队列摘要发现持续压力，由目标端串行发放按估计工作量计量的额度，再转发一批尚未执行的请求。

候选贡献是：在反馈和通信成本下联合决定触发时机、接收工作量和批次大小；不是泛称发明批量或主动迁移。主张是否成立由冻结工作负载上的对比和消融决定，允许得出负面结果。

## 固定边界

- 同机架副本；无状态或目标已有数据的请求；不迁移运行状态。
- 每主机一个共享 FIFO，固定多个执行核心，另留一个控制核心；所有方法具有相同硬件预算。
- 请求类型在到达时可见，真实服务需求仅供离散事件执行引擎使用。预测使用类别配置均值和本机可观测容量，不能读取未来完成时间。
- 请求轨迹预生成，记录 SHA-256；所有策略重放同一个输入。算法抽样与输入生成完全独立。
- 负载率按含主机开销的平均占核时间归一化；容量下降是外生事件，不人为限制入口候选来制造热点。
- 到达窗口固定，预热请求不统计但参与执行；停止到达后排空所有请求。
- 初始单向网络延迟沿用 3.15 μs，主机开销 2.1 μs；均为可替换假设，不能称为实测现代硬件成本。

## 协议和算法

1. 入队/出队根据可见类别更新总工作量；不每周期扫描全队列。
2. 低频有界检查只读本地摘要和延迟收到的远端摘要。摘要包括队列工作量、占用核心的估计工作量、本机容量与时间戳。
3. 预计等待超过门限且有绝对收益时，选择有限候选目标。请求数、总估计工作量和字节数均设上限，不等待凑批。
4. 向目标申请额度。目标在自己的控制线程串行检查当前排队与已有额度，返回带有效期的接受量。
5. 源端收到额度后重新检查队列，从队尾取走仍未执行的请求；转交时改为在途状态。目标确认前任务仍可被本机领取，避免无谓冻结。
6. 目标收到数据后消费额度，过期数据拒收并回退源端。每个请求最多尝试一次数据转发，回退后不再迁移。故障模型初版包含额度超时，不包含主机崩溃与丢包重试。

控制 CPU 与链路各自串行服务；申请、返回、转发、释放都经过事件延迟。不同源端不能读取即时全局预留数组。批次可在目标收到后被多核独立执行。

## 对比方法

| 实验名称 | 实现含义 | 复现范围 |
| --- | --- | --- |
| p2c | 缓存队列长度的 Power-of-2 | RackSched 的入口策略思想，不声称复现 P4、请求亲和表与抢占完整系统 |
| jsw | 所有主机的缓存工作量，计入入口在途增量 | 强入口参考；QBR 与其他修复方法使用相同入口 |
| jbsq | 入口中心排队，限制每主机未完成数，完成反馈后恢复额度 | R2P2 的 JBSQ 主机级策略复现，不包含原网络协议 |
| steal | 空闲主机根据缓存压力请求批量窃取 | 反应式拉取对照，有通信和接收预留 |
| threshold | 固定上限批次的源压力转发 | 与 QBR 共用额度协议，隔离复杂收益判据的增量 |
| single | QBR 的单请求版本 | 相同信息、阈值和协议，比较摊销收益 |
| qbr | 工作量/字节/SLO 收益约束的批量重调度 | 本项目候选算法 |
| work | JBSQ 请求数上限之外再增加估计工作量约束 | 试验性候选；实验显示保守准入损害吞吐 |
| bwc | work + 聚合完成额度反馈 | 试验性候选；负面结果完整保留 |

另做无接收预留、固定批量上限、反馈年龄和网络/控制成本消融。Pallas 的分组重配置与复制、Capybara 的 TCP 连接迁移具有不同语义，本轮不把简化转发算法冒称为它们的完整复现。

## 评测与判定

包括平稳、局部容量下降、全局突发/过载边界与长尾服务；扫描负载和至少 10 个独立种子。对同轨迹的 SLO 违约率、P99、P99.9 做配对差值与区间估计。报告吞吐、迁移比例、批次大小、控制 CPU、网络字节、拒绝与额度超时，以及每请求完成一次等不变量。

正式实验另设单主机短暂停顿，区分机架尚有余裕的失衡与机架总能力不足。主实验 1800 次，敏感性/消融 2840 次；种子 11–20，试跑种子 101–102。`v1/v2` 为诊断试跑，`v3` 为正式冻结模型。不可把试跑和正式结果混合汇总。

迁移质量以同一输入上 jsw 无修复运行的请求延迟作反事实参照：迁移请求未变快的比例记为 invalid_migration_ratio。这个指标包含全局干扰变化，不解释为单次迁移的孤立因果效应。

如果 qbr 不优于 threshold/steal，报告这一结果并采用更简单机制，不通过场景专用参数掩盖失败；如果强入口已消除空间，收窄或停止迁移主张。仿真闭环和真实集群/SmartNIC 验证必须分开标注。
